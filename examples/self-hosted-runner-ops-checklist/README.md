# self-hosted runner 運用チェックリスト（最小）

self-hosted runner は強力ですが、運用設計を誤ると「任意コード実行」の影響がホストへ直接波及します。最低限、次を明文化してから導入してください。

## セキュリティ（信頼境界）

- **原則：fork PR 等の不特定入力を self-hosted で実行しない**
- runner グループ/ラベルで用途別に分離する（例：`gpu`、`deploy`、`trusted-only`）
- 可能なら ephemeral（使い捨て）にする（VM/コンテナで隔離）

## 運用

- patch 適用/再起動/退役（ローテーション）の手順を用意する
- キャッシュは汚染を前提に扱う（Secrets 混入・改ざんを想定）
- `concurrency` とキュー設計で過負荷を制御する

## トラブル時の確認

- runner が online か（サービス稼働、ネットワーク）
- `runs-on` のラベルが一致しているか
- リポジトリ/組織の許可範囲に含まれているか
