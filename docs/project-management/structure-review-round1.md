# 1. 書籍の概要

- 想定読者（既存記述ベース）
  - GitHub の基本は理解しているが、AI ツール（ChatGPT / GitHub Copilot / Claude 等）を前提とした開発ワークフローを体系的に整理したい開発者・チーム。
  - チームの生産性向上を目的に、Issue / Pull Request / CI/CD / 権限設計 / セキュリティ運用を「AI 協働」を前提に見直したいリーダー・運用担当。
- 本書で達成しようとしているゴール（既存記述ベース）
  - AI 協働を前提とした GitHub ワークフローの全体像を理解し、プロジェクトの状況に合わせた基本フローを設計できるようにする。
  - GitHub Actions / Advanced Security / 権限管理などを組み合わせ、AI 開発プロジェクトに必要な自動化・セキュリティ・ガバナンス基盤を構築できるようにする。
  - 組織としての AI ツール利用方針、レビュー体制、CI/CD の設計・改善における判断材料を整理できるようにする。

# 3. 構成上の気になる点（候補）

- 「はじめに」系の情報の不整合
  - `docs/introduction/index.md` の部構成（章範囲）が、`docs/index.md`（目次）や `docs/_data/navigation.yml`（ナビゲーション）と一致していない。
  - 読者は「どこまでが基礎で、どこからが応用か」を序盤で誤認しやすい。
- 章内の節番号が章番号と一致しない箇所がある
  - 例: 第3章に `## 2.6 ...`、第4章に `## 3.x ...` が混在するなど（第3〜14章で複数箇所）。
  - 初学者が参照（「3.6 を参照」等）する場面で混乱し、自己学習の進捗管理も難しくなる。
- 章内に「サンプル/テンプレート」が見出しとして混入している可能性
  - 第5章に `## Features / Installation / Quick Start ...` といった英語見出しが続く（リポジトリ README テンプレート由来の可能性）。
  - 第10章・第11章・第16章でも、組織 README / Security Policy / PR テンプレート等に見える見出しが混在している。
  - 意図して掲載している場合でも、「本文」と「テンプレート例」の境界が曖昧になりやすい。
- ナビゲーション（付録）の表記不整合
  - `docs/_data/navigation.yml` の `appendix-g` が「第16章：コンプライアンスとガバナンス」となっており、章番号・章名と競合している（付録名の誤記の可能性）。
- 章頭の学習目標の提示形式が統一されていない
  - 第2章以外は章頭の「学習目標/この章で学ぶこと」が明示されていない（章末に「確認事項」はある）。
  - Stage2 の要件である「章の学習目標と節内容の対応」を、読者が自己点検しづらい。

# 4. 構成改善の提案（案）

- はじめに（構成説明）の整合性を回復する
  - `docs/introduction/index.md` の「本書の構成（各部の章範囲）」を、`docs/index.md` と一致するように更新する。
  - `docs/_data/navigation.yml` の序章タイトル（「序章」）と、本文側の表記（「はじめに」）の統一方針を決めて揃える（例: ナビも「はじめに」へ）。
- 章内の節番号のずれを機械的に補正する（第3〜14章）
  - 第3章: `2.6` → `3.6`
  - 第4章: `3.x` → `4.x`
  - 第5章: `4.4/4.5` → `5.4/5.5`
  - 第6章: `5.5` → `6.5`
  - 第7章: `6.x` → `7.x`
  - 第8章: `7.x` → `8.x`
  - 第9章: `8.x` → `9.x`
  - 第10章: `9.x` → `10.x`
  - 第11章: `10.x` → `11.x`
  - 第12章: `11.x` → `12.x`
  - 第13章: `12.x` → `13.x`
  - 第14章: `13.x` → `14.x`
- 「テンプレート例」を本文から視覚的に切り離す
  - 第5章・第10章・第11章・第16章に含まれるテンプレート由来とみられる部分は、見出しではなくコードブロック（例: ` ```markdown`）にするか、付録へ移動して参照リンクを張る。
  - これにより、章内の「導入 → 本論 → まとめ」の流れを維持しつつ、読者がテンプレート部分を安全に読み飛ばせる。
- 章頭に「この章で扱うこと（2〜4項目）」を統一形式で追加する（提案）
  - 章末の「確認事項」と対応するように、章頭で到達点を先に提示する。
  - 内容は既存の節見出し・まとめ・確認事項から抽出し、意味変更のない範囲で整形する。
- 付録Gの名称を付録としての表記に修正する
  - `docs/_data/navigation.yml` の `appendix-g` を「付録G：参考資料」等の付録名に修正し、章番号と衝突しないようにする（付録の正式名称は本文側記述に合わせて要確認）。
